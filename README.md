How to run 
1.	Open decoupled_profile_generation_bias.ipynb 
2.	Runtime → Change runtime type → GPU 
3.	Upload the zip 
4.	Run the notebook top-to-bottom

What the code does
1. Recommendation performance
1) Loads inputs
•	Train triplets (profile → positive track, negative track) and test candidates (per query_key, includes positives + negatives)
•	Profile files for Gemini / LLaMA / DeepSeek
•	Track metadata pools for building track texts
2) Trains a bi-encoder (SentenceTransformers), runs 1 epoch for one seed
•	Base encoder: sentence-transformers/all-MiniLM-L6-v2
3) Evaluates retrieval performance
•	Metrics: Recall@10 and NDCG@10
•	Produces per-query results CSV + summary CSV
4) Saves outputs
Outputs are written under: /content/eval_outputs_seed42/ 
2. Bias Analysis
The notebook also includes a faithfulness-based bias analysis of the generated profiles (Gemini, LLaMA, and DeepSeek). For each profile, we compute:
•	Unsupported claim rate – the proportion of claims not grounded in the user’s tracks.
•	Genre coverage – how much of the interaction-supported genre information is preserved.

A note about code files: 
The file decoupled_profile_generation_bias.ipynb is meant for your run, it includes the training and evaluation part for recommendation performance (recall@10 and ndcg@10), and the bias analysis part. In this file we only ran the training on 20 users, the runtime should take at most 12-14 mins. If you want to reduce runtime, go to cell number 5 to this part:
# Subsample to 20 users 
N_USERS = 20
SEED_USERS = 42  
And change N_USERS = 20 to a lower number (in our original code file we used 50 users).
The file Evaluation_recommendation_bias.ipynb includes all the steps we took in the work of our project. In case you want to check out what we did in this file, here’s an explanation of each step:
In cells 1 – 7 we filled the Lastfm.1k dataset with missing data and preprocessed to produce the datasets we used for recommendation performance and bias analysis (the datasets csvs in csv_for_run.zip). 
In cells 8 – 15 we generated profiles by the 3 LLMs that we used – we produced a csv including profiles produced by each LLM, which can also be found in csv_for_run.zip.
In cells 16 – 20 we implemented the training and evaluation part for recommendation performance and implemented a bias analysis on the profiles generated by the 3 LLMs.
All the results presented in the report we produced using this file (Evaluation_recommendation_bias.ipynb). 
The file lastfm.1k_dataset.ipynb is where we extracted the Last.1k dataset (it was too large to open on excel) so we opened in colab and took the first 1.8m rows, and then we sampled 50 users with their relevant data, and sampled the data relevant to the negative tracks we used in the 1000 pool and 500 pool, we formed all our datasets using this dataset.

The contents of csv_for_run.zip:
train_triplets_with_gemini_llama_deepseek_profile_ids.csv
Training triplets linking each profile (from all three LLMs) to one positive track and one sampled negative track.
 test_candidates_with_gemini_llama_deepseek_profile_ids.csv
Test set containing, for each user–window, 10 positive tracks and a set of negative candidate tracks used for ranking evaluation.
generated_profiles_gemini.csv
User-facing and recommendation-optimized profiles generated by Gemini for each user and time window.
generated_profiles_llama.csv
User-facing and recommendation-optimized profiles generated by LLaMA for each user and time window.
generated_profiles_deepseek.csv
User-facing and recommendation-optimized profiles generated by DeepSeek for each user and time window.
50_users_tracks_top15_enriched_.csv
The top-15 most listened tracks per user–window, enriched with metadata (genres, country, release year) used for profile generation and bias analysis.
train_pool_1000_set.csv
The pool of candidate tracks used to sample negative examples for training.
test_pool_500_set.csv
The pool of candidate tracks used as negatives in the test ranking evaluation.
